# Documentation Steering

## Purpose

This project documents both the software prototype and the AI-assisted development process.

Documentation is part of the research design and should support the later evaluation of the vibe coding approach.

---

## Documentation Principles

- Document relevant decisions, not every minor detail.
- Prefer short, structured Markdown files.
- Keep documentation close to the related project artifact.
- Avoid duplicated or conflicting documentation.
- Write documentation in German unless a file or artifact is explicitly intended for GitHub publication in English.

---

## Documentation Locations

### Development Sessions

Development sessions are documented under:

```text
docs/research/
```

Namensschema: `session-000.md`, `session-001.md`, ...

### Code Reviews

Code reviews are stored under:

```text
docs/reviews/
```

Namensschema: `review-001.md`, `review-002.md`, ...

### Architecture Decisions

ADRs are stored under:

```text
docs/decisions/
```

### Game Concept

### Architecture

### Prompts
