# ADR-005: MVP First

## Status

Accepted

## Context

The project has limited time and token budget. Attempting to build a full-featured application risks an incomplete or unstable result.

## Decision

Follow an MVP-first approach: implement one complete, playable level with core mechanics before adding additional features.

## Consequences

- Always have a working, demonstrable prototype
- Features are added incrementally and can be evaluated individually
- Reduces risk of overengineering
- Thesis evaluation can proceed even if not all planned features are completed
- Scope is explicitly limited (no accounts, no multiplayer, no admin area)
